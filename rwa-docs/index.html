Seed RWA architecture Solana devnet

How dnevnik.live tokenizes physical CBD plants as real-world assets (RWAs) on Solana: token standards, growth minting, marketplace and redemption flow.

1. RWA architecture

Each physical seed adopted on dnevnik.live is represented by a Seed NFT — a Metaplex NFT in the verified dnevnik.live Seeds collection. The NFT is the on-chain record of the asset; the public grow journal is the off-chain evidence trail. The two are linked in both directions: the NFT metadata references the journal plant ID, and the app shows the on-chain mint address, transactions and metadata for each token.

Components

  • App (dnevnik.live/app) — Firebase-authenticated grow journal. Users connect a Solana wallet (multi-wallet or watch-only) and link it to their account by signing a message.
  • Seed NFTs — one per physical seed; strain, batch and linked plant ID live in the metadata (Arweave, uploaded via Irys).
  • $GROWTOO SPL token — fungible reward token (9 decimals). Minted to holders as their plants advance growth stages; used as the marketplace currency.
  • Mint queue — mint and settlement requests are filed in Firestore; an authority-operated worker executes them on devnet and writes back transaction signatures. This queue is the devnet stand-in for backend services / on-chain programs planned for mainnet.

Trust model (devnet MVP)

On devnet, the collection authority also acts as metadata update authority, $GROWTOO mint authority and marketplace escrow. Growth-stage updates are only executed by the authority after the corresponding journal progress exists, and rewards are computed server-side. The mainnet path replaces the queue with an on-chain escrow program and oracle-verified growth attestations.

2. Token standards

Seed NFT (non-fungible)

Metaplex Token Metadata standard, extended with a machine-readable rwa block. Full JSON Schema: seed-rwa.schema.json. 

{
  "name": "CBD Auto #1",
  "symbol": "SEED",
  "image": "…",
  "attributes": [
    { "trait_type": "Strain",  "value": "CBD Auto" },
    { "trait_type": "Batch",   "value": "B-2026-07-A" },
    { "trait_type": "Stage",   "value": "Flowering" },
    { "trait_type": "Plant ID","value": "plant-abc" }
  ],
  "rwa": {
    "standard": "dnevnik.live/seed-rwa",
    "version": "1.0.0",
    "assetType": "flower",
    "strain": "CBD Auto",
    "batch": "B-2026-07-A",
    "plantId": "plant-abc",
    "cluster": "devnet",
    "importedAt": "2026-07-10T00:00:00Z",
    "growthHistory": [
      { "stage": "germination", "reward": 10, "ts": "…", "signature": "…" }
    ]
  }
}

The metadata URI is updated at every growth stage; rwa.assetType flips from seed to flower at the flowering stage, which is what makes seed RWAs and flower-stage tokens two distinct tradeable asset types on the marketplace.

3. Growth minting flow

  1. User documents growth in the journal and advances the plant token a stage in the app.
  2. The app files a growthMints request referencing the Seed NFT mint address.
  3. The worker uploads new stage metadata to Arweave (Stage trait + growthHistory) and updates the NFT metadata URI on-chain.
  4. The worker mints the stage's $GROWTOO reward to the holder's wallet.
  5. The app displays the real transaction signatures (Solscan links) in the token's history.

4. Marketplace (devnet MVP)

  1. List: the seller signs a transfer of the NFT to the marketplace escrow wallet and the listing goes live with a $GROWTOO price.
  2. Buy: the buyer signs a $GROWTOO payment directly to the seller.
  3. Settle: the worker verifies the payment on-chain and releases the NFT from escrow to the buyer. Sellers can cancel live listings; the NFT is returned.

The swap is escrow-mediated rather than atomic — an accepted trade-off for the devnet MVP. Mainnet uses an on-chain escrow program so neither leg depends on the operator.

5. Redemption flow

Redemption converts the on-chain asset back into its real-world counterpart (harvest share of the plant, subject to applicable regulation).

  1. A harvest-stage NFT holder requests redemption in the app (planned M5; devnet mock until then).
  2. The redemption burns the NFT (or marks it redeemed via a frozen redemption trait), permanently retiring the claim.
  3. The operator fulfils the physical delivery / payout recorded against the batch code, and publishes the fulfilment reference in the journal.
  4. $GROWTOO earned by the plant remains with the holder — only the asset NFT is retired.

6. Deployed addresses (devnet)

Published after the M1 devnet deploy in the repository (chain/deployed.devnet.json) and in the app's chain config. All assets are on devnet — they carry no monetary value.
