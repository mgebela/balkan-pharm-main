What this proposes

One preference — Light / Dark / Auto — in the account menu, stored on the user doc so it follows the grower across devices, with prefers-color-scheme as the fallback before the doc loads.

The one real design decision

Brass #c9a55e on cream fails contrast as text. So in light mode the accent splits in two: --brass drops to #7d6024 for text, icons and links, while --brass-fill keeps the gold for buttons, the chart bars and the wax seals.

That split is why light mode still reads as growtoo instead of as a generic light app — and it's the reason a mechanical find-and-replace of the palette would not work.

Measured against the light card surface #fffefa — every pair clears AA (4.5:1):

/* the problem */
#c9a55e brass as text      2.31:1  ✗ fails

/* the fix */
#7d6024 brass ink          5.83:1  ✓
#17251b body text         15.80:1  ✓
#253a2a muted (72%)        5.12:1  ✓
#3d6a38 ok / sealed        6.27:1  ✓
#8d5233 warn / due         6.14:1  ✓
#241a05 on gold fill       7.37:1  ✓

Also not an inversion

  • Cards gain a hairline shadow. Dark mode gets away with flat borders; on paper every card dissolves into the page without a little lift.
  • The canvas keeps its two radial glows, warmed and strengthened — flat cream reads as unfinished next to the dark build.
  • Status colours re-derive: --green #b8d4b0 → #3d6a38, --rust → #8d5233. The pale versions vanish on cream.
  • Wax seals invert their fill but keep the dashed brass ring — the motif survives intact, which is the test that matters.

What the port actually costs

12,435lines in app.css
980hardcoded colours
940existing var() uses

app/styles/app.css is roughly half-tokenised: 233 hex literals and 747 rgba() literals sit outside the token layer. Those are the work — not the :root block, which is the easy part.

The token layer to add

/* app/styles/app.css */
:root {
  /* existing brand tokens stay exactly as they are */
  --brass: #c9a55e;

  /* new: what today sits inline as literals */
  --brass-fill: #c9a55e;
  --brass-wash: rgba(201,165,94,.08);
  --sidebar-bg: rgba(12,20,14,.94);
  --header-bg: rgba(15,26,18,.78);
  --metric-bg: rgba(10,18,14,.96);
  --seal-bg: radial-gradient(…);
  --ok-text: var(--green);
  --warn-text: var(--rust);
  --shadow-card: none;
}

:root[data-theme="light"] {
  --brass: #7d6024;   /* ink weight */
  --brass-fill: #c9a55e; /* still gold */
  --text: #17251b;
  --bg: #f3f0e7;
  --card-bg: #fffefa;
  --shadow-card: 0 1px 2px rgba(60,50,20,.05);
  /* …the rest of the semantic layer */
}

Suggested order

  1. Land the token layer on dark only. Zero visual change — every new token resolves to the value already there. Safe to ship on its own.
  2. Sweep the literals view by view — shell, journal, plants, market, coach, tools. Still dark-only, still no visual change, reviewable in small diffs.
  3. Add the light block and the account-menu control. Only now does anything look different.
  4. Landing page (styles/landing.css) last, if you want the marketing site to follow.

Steps 1 and 2 are the bulk of it and carry almost no risk — that's deliberate. The reason to do it in that order is that a half-swept sheet in light mode looks broken in ways that are hard to find, so the sweep should be finished and shipped before the theme exists at all.

Decided — dark is the default

Dark is the identity the catalog system was drawn for, so it stays the baseline. Auto is available but opt-in — defaulting to Auto would hand first impressions to whatever the visitor's OS happens to be set to.

What that means concretely:

  • Dark is the unthemed state. No data-theme attribute on <html> means dark, so a user who never opens the menu — and the first paint before the user doc loads — get dark with no flash.
  • Only light is ever written to the attribute. Auto resolves to light or nothing, it is never a value in the DOM.
  • The stored preference defaults to 'dark', not 'system', so the choice survives across devices rather than re-deriving per machine.
  • No @media (prefers-color-scheme: light) block anywhere — the OS only gets a say once the user has explicitly picked Auto.
